## Context

控制页以 `ControlMode`、`Handedness`、`GyroMode` 和 `GyroHandMode` 的组合决定触控布局。当前页面直接在 `_ControlArea` 中选择控件：普通双控和一部分单通道体感已选择浮动单轴控件；单手双轴控件与体感双手控件却绕过 `ControlMode`，造成行为不一致。现有浮动控件的容器尺寸也接近控件自身尺寸，不能表达“在侧边操控区域任意起点开始”的需求。

项目要求单文件不超过 200 行、控制层高内聚、非 UI 逻辑具备单元测试；`File.md` 要记录新增核心文件。

## Goals / Non-Goals

**Goals:**

- 所有存在触控主控的手型与单通道体感布局均响应 `fixedPosition` / `floating`。
- 隐藏可变模式下，控件在对应完整有效操控面按下时出现，以该点为原点，松手后隐藏并将触控输出归零。
- 不改变每个布局已有的通道映射、正负向限制、微调位置和停车锁定行为。
- 将布局决策和可复用浮动控件拆离页面。

**Non-Goals:**

- 不新增、删除或迁移任何设置字段。
- 不改变体感同时控制方向与油门时无触控主控的规则。
- 不修改蓝牙协议、控制心跳、油门档位或通道 PWM 映射。

## Decisions

### 1. 使用纯布局策略统一组合判断

新增纯 Dart 布局策略，将设置组合映射到“固定控件 / 左侧浮动面 / 右侧浮动面 / 双侧浮动面”和对应通道、方向约束。`control_page.dart` 仅装配策略返回的控件与回调。

选择此方案是为了让全部组合可用单元测试覆盖，避免继续把模式判断散落在 Widget 分支中。备选方案是在每个现有 `switch` 内增加 `controlMode` 条件；其重复多且容易遗漏新手型，故不采用。

### 2. 浮动模式的命中范围是布局对应的操控面

将每个浮动控件放进与左侧、右侧或单手侧相对应的扩展触控面，而非仅放进控件原尺寸的盒子。浮动控件仍在该面内钳制视觉原点；方向/油门微调位于更高层，优先接收自身范围内的触摸。

这既符合“任意起点”要求，也不影响微调交互。备选方案是仅扩大现有 `width` / `height` 常量；它无法统一处理左右侧和二维单手区域，因此不采用。

### 3. 单手模式新增二维浮动控件

为单手左边、单手右边增加 `FloatingFourDirectionControl`。它复用现有四方向素材及 `FourDirectionValue` 输出，在按下时显示四方向视觉，依据相对原点的二维位移输出方向与油门，并在结束时同时归零。

单轴浮动控件不能被两个实例叠加替代，因为两个手势识别器会竞争同一指针，无法保证一次拖动同步产生两个通道输出。

### 4. 双手体感隐藏模式使用与固定模式相同的单向半控件

仅方向体感的双手布局：左侧仅允许倒车，右侧仅允许前进；仅油门体感的双手布局：左侧仅允许左转，右侧仅允许右转。隐藏模式必须使用与固定模式一致的单箭头半控件，仅将控件出现位置改为按下位置；不得复用会同时绘制正反两个箭头的通用双向浮动控件。

这确保改动只改变控件位置与可见性，不改变用户已经习惯的操控语义和视觉样式。

### 5. 按现有状态入口提交输出

所有新控件通过 `ControlController.setSteering` 和 `setThrottle` 提交值，不直接写接收机。停车锁定、档位、体感覆盖和发送节流继续由既有控制器处理。

## Risks / Trade-offs

- [扩展触控面可能与微调区域重叠] → 微调保持在 Stack 顶层，并为浮动视觉与输入区域添加 Widget 测试。
- [组合数量较多，易遗漏] → 布局策略参数化测试覆盖手型、体感类型、操控模式和单侧约束。
- [边缘按下可能裁切控件] → 控件以触控面尺寸钳制原点，测试四个边缘与小尺寸容器。
- [二维浮动控件改变油门手势感受] → 复用固定四方向控件的方向/油门归一化与松手归零语义，仅将中心点改为本次按下位置。

## Migration Plan

该变更不涉及存储迁移。发布后，已保存为 `floating` 的用户会立即在原本固定的单手和体感双手布局中获得隐藏可变行为；保存为 `fixedPosition` 的用户维持原布局。若出现触控回归，可回退本次控制页 Widget 与策略文件，不影响设置数据和接收机状态。

## Open Questions

无；双手单侧正负向限制按现有行为保留。
